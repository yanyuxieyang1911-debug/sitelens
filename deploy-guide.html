SiteLens 上线指引

把已推到 GitHub 的 SiteLens 变成公网可访问的服务。两种一键路径，二选一即可。

整体流程

第 ①② 步已完成：代码已在 github.com/yanyuxieyang1911-debug/sitelens， 你只需做 ③④（在平台点几下）。

推荐 Railway

步骤

  1. 打开 railway.app，点 Login → 选 GitHub 授权登录。
  2. 登录后点 New Project → Deploy from GitHub repo。
  3. 在列表里选中 yanyuxieyang1911-debug/sitelens（搜 "sitelens"）。
  4. Railway 自动读取仓库里的 railway.json（Docker 构建），无需改任何配置。
  5. 等待构建完成（约 1–2 分钟），状态变 Success。
  6. 点顶部的 Generate Domain（或 Settings → Domains）→ 拿到一个 *.up.railway.app 公网地址。
  7. 浏览器打开该地址，输入任意域名开始分析 🎉
费用：免费额度含 500 小时/月，个人够用；超了才计费。环境变量 PORT 由平台自动注入，无需手动设。

Render

步骤

  1. 打开 render.com，Sign Up → 选 GitHub 授权。
  2. 控制台点 New → Web Service。
  3. Connect 你的 GitHub，选中 yanyuxieyang1911-debug/sitelens。
  4. Render 读取仓库 render.yaml（Docker 运行时），基本无需改。
  5. 确认 Plan: Free，点 Create Web Service。
  6. 等待首次构建部署（免费套餐会先休眠，首次访问冷启动 30–60s，属正常）。
  7. 部署完成后得到 *.onrender.com 公网地址，直接访问。
冷启动：免费套餐无流量时会休眠，第一次点开要等半分钟。付费或加 "Keep alive" 可消除。

部署后必读

  • 出口网络：服务器需能访问目标站点及 tranco-list.eu / index.commoncrawl.org / rdap / googleapis.com（PageSpeed）。某源不可达会自动降级，报告仍可用。
  • 限流（重要）：公开部署建议在前层加基础限流（Nginx limit_req 或 Cloudflare），避免被当抓取代理滥用。单域名单次分析约抓十余请求、耗时 10–30s。
  • SSRF 防护：工具已内置，禁止分析 localhost / 私有网段（10/172.16/192.168/127 等）及解析到内网的域名。
  • 流量是估算：Tranco 排名为一手数据；月访问量是经验模型估算，报告内逐条标注口径，请勿当精确指标对外承诺。

常见故障

  1. 构建失败 / 健康检查红：确认仓库根有 Dockerfile 与 railway.json / render.yaml（已备好）；看平台构建日志是否卡在拉取基础镜像。
  2. 页面打不开：先访问 /api/health，返回 {"ok":true} 说明服务存活；否则看运行时日志。
  3. 分析一直转圈：多半是服务器出口被墙/超时，工具会降级并在报告标注"数据源不可用"，不是代码 bug。
